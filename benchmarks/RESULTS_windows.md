# PyDB benchmark results — Windows

Generated by `python benchmarks/run_benchmarks.py --rows 5000` — real measurements from one run.

- PyDB 0.1.0, Python 3.10.11 (CPython)
- Windows 11 (build 26300; Python's `platform` module reports it as "Windows 10") on AMD64
- 2026-10-31 14:21:10

| Benchmark | Result | Notes |
|---|---:|---|
| bulk insert (1 transaction) | 3,717 rows/s | 1.35 s total |

| full sequential scan | 228,835 rows/s | 23.2 ms for 5,300 rows |
| point lookup via B+ tree (IndexScan) | 0.156 ms/query | 200 queries |

| primary-key B+ tree shape | height 2 | 36 leaves, 1 internal nodes |

| GROUP BY over whole table | 109 ms | 100 groups |
| buffer pool hit ratio (whole run) | 100.00% | 26,767 hits / 0 misses, 0 evictions, 256 frames |
| startup time (open existing DB) | 57 ms | file 0.5 MiB, 140 pages scanned |

Interpretation: the B+ tree turns a point lookup from reading every page of the
table (O(n)) into a root-to-leaf walk of a few pages (O(log n)). Autocommit inserts
pay for a WAL fsync on every COMMIT, so batching writes in one transaction is faster;
how large the gap is depends on the fsync latency of the disk.
